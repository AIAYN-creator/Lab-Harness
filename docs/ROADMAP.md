# Roadmap

Where LabHarness is going, and the design rules v0.1 must respect so that later versions never
require rewriting the core.

## v0.1 — Demo-ready MVP *(released: 0.1.0)*

**Goal:** a live, fully working demo of the loop data or SMILES → figure → PDF, on the author's
Windows laptop.

**Includes:** chemical structures (RDKit) with offline IUPAC name resolution, mechanisms and
diagrams (TikZ/chemfig), regressions and plots (SciPy/Matplotlib), the event-driven watcher, the
ACS template with a single document-wide typeface, modular installation, and agent context files.

**Done when:** the demo runs end to end without manual intervention beyond saving files.

## v0.5 — Daily use *(current)*

**Goal:** the author uses it every day with real research data (asymmetric catalysis).

**Includes:** editorial LaTeX tables (booktabs/siunitx), real scientific rules in `AGENTS.md`,
`labharness eject`, technical protection of `data/`, reading real instrument exports robustly, and
an optional lab compound library so compounds can be referenced by their in-house code, with a
warning when a chiral compound has no stereochemistry. Already on `main`: `labharness add` and
`labharness preview`, tables, the agent rules, `eject` and the protection of `data/`.

**Done when:** a chapter of the author's thesis has every figure and table generated by
LabHarness. There is no date.

## v1.0 — Public release

**Goal:** publish the repository and earn the first organic stars, with no artificial target.

**Includes:** Elsevier (`elsarticle`), an RSC working format (`rsc-draft`) and short and long
documents for lab work (`article`, `report`), each a journal folder with its own
style file; choosing the typeface from a tested catalogue when a project is created, and a
configurable LaTeX engine; a full LaTeX build that no longer needs Perl; publishing to PyPI; CI on
macOS; a manifesto README; and governance for external contributors — pull requests with green CI
and maintainer approval, security alerts, and protected release tags.

**Done when:** someone outside the project can install LabHarness from the README alone and
generate a figure without help.

## v1.5 — A modular LabHarness

**Goal:** anyone can build a package with the modules, figure templates and agent rules their
field needs, without touching the core (ADR 30 and 31).

**Includes:** the domain contract, with chemistry as its first domain; the first new domains, in
the order the demand sets: economics (regression tables from statsmodels), mathematics (TikZ and
pgfplots templates) and construction (.bc3 budgets, .dxf plans); bar charts and heat maps; online
name resolution through PubChem, behind an explicit flag; and a working environment that opens
the manuscript, the console and the PDF side by side, with the PDF on either side.

**Goes ahead** whether or not v1.0 draws outside users: the author uses it.

## v2.0 — Graphical interface

*Only if v1.0 validates the pipeline and there is demand.* A separate product for people who do not
use a terminal: the existing modules wrapped in a graphical interface, with compilation hidden and
an editable code panel that keeps the human in the loop.

## Design rules v0.1 must respect

| # | Rule | Required by |
|---|---|---|
| 1 | Modules are importable functions, with no terminal or watcher logic | v2.0 |
| 2 | Style is data, with one typeface per document defined in a single place | v1.0 |
| 3 | Journal templates are interchangeable folders | v1.0 |
| 4 | Adding a module or a domain does not touch the core | v0.5, v1.5 |
| 5 | Reading data is separate from drawing | v1.5 |
| 6 | The data-to-figure relationship lives in a readable file | v2.0 |
| 7 | Works offline; anything needing the network sits behind an explicit flag | Local-first |
| 8 | The LaTeX engine is configurable | v1.0 |
| 9 | Everything an agent generates is readable, runnable code | All |
| 10 | Modular install: the core does not depend on RDKit, SciPy or Matplotlib | v1.5 |
| 11 | Modules only use the public API of the core and the style | v0.5 (`eject`) |
| 12 | CI job names are stable and the ruleset is versioned | v1.0 |

## Risks being watched

- **Latency.** The reference is 0.5 s from save to updated PDF; LaTeX may not get there. Measured
  per phase from day one.
- **System dependencies on Windows:** Java and a non-locking PDF viewer. Each one is a failure
  point in a demo and a barrier to entry later. Perl is on its way out (ADR 25).
- **SVG to PDF fidelity** for RDKit structures.
- **Legibility of Latin Modern** in small atom labels.
